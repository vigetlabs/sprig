# Seed-planting memory optimizations

Seven commits, applied in order on top of `master`, that reduce Sprig's memory use on
large seed-data runs (and fix one real correctness bug along the way). Full mechanism,
empirical evidence, and reproduction steps for each lived in a separate benchmarking
effort not included on this branch; this file is the concise version -- for each commit,
what changed and why it matters.

| #   | Commit                                                                                          | Change                                                                                                                                                                                                                                                                                                                                                                  | Why it matters                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `fde22f9` Introduce `Seed::Descriptor`; defer `Entry` materialization to plant time             | Every parsed row used to become a fully-built `Seed::Entry` (attributes wrapped, values pre-processed) the instant it was read. It now becomes a lightweight `Descriptor` (raw row + class + options); the real `Entry` is only built at the instant a record is actually saved.                                                                                        | Anything still waiting on a dependency sits in memory as _something_ until that dependency resolves. A `Descriptor` costs a fraction of a built `Entry` (~1,552 bytes vs. ~7,168 bytes, measured), so the "something" is far cheaper for every record that has to wait.                                                                                                            |
| 2   | `fbb4324` Deterministic `Dependency`; stop memoizing `Descriptor#dependency_id`/`#dependencies` | `Dependency#id` was a cached random UUID, kept alive forever in a global registry purely so a second lookup would return the same id. It's now a deterministic string computed from class + sprig_id, so no registry is needed at all.                                                                                                                                  | A global registry that remembers everything it's ever handed out, for the life of the process, grows without bound and never shrinks. Making the id reproducible removes the need to remember it entirely.                                                                                                                                                                         |
| 3   | `25aa1ed` Replace whole-graph tsort with incremental plant-when-ready scheduling                | Sprig used to build and topologically sort the _entire_ dependency graph before planting anything. It now plants a record the instant everything it depends on is already planted, holding only what's genuinely still blocked.                                                                                                                                         | **This is a correctness fix, not just a memory one.** The old sort recurses per node; a long self-referencing chain declared newest-first overflows Ruby's stack (verified: a 20,000-record chain crashes the old scheduler, plants cleanly on the new one). It's also cheaper: only truly-blocked descriptors are held, and "planted" bookkeeping is a bare string.               |
| 4   | `9da2567` Stop retaining full records in `SprigRecordStore`; re-fetch lazily by id              | The store used to keep the actual saved record object alive for the whole run, purely so a later `sprig_record(Klass, id)` could look it up. It now stores just `record.id`, and returns a `LazyRecord` that answers `.id` with zero database access, falling through to a real fetch only if something more is asked of it.                                            | A live ORM record is far heavier than the row it represents -- every column is its own wrapper object. `sprig_record(...)` is overwhelmingly used just to read the id back off for a foreign key, exactly the case that now costs nothing. Measured: roughyl 40% reduction in peak memory use for 10K record datasets.                                                             |
| 5   | `0ebf875` Stream YAML/JSON parsing directly off IO instead of loading whole file                | Parsing used to load an entire seed file into memory as one big nested structure (`YAML.load`/`JSON.load`) before a single row was processed. It now streams one row at a time directly off the file handle.                                                                                                                                                            | The old approach's peak memory scaled with total file size, regardless of how the rest of the pipeline behaved. This was the single largest contributor in the whole stack at medium/large scale (measured: -49.5% at medium tier, -58.7% at large tier vs. the prior commit), because it's the one change that removes an _entire copy of the input data_ from memory.            |
| 6   | `109bf26` Add opt-in `spill_seed_rows_to_disk`; add architecture walkthrough doc                | New, off-by-default config option: a descriptor that's genuinely determined to be blocked (not every descriptor) spills its raw row data to a small disk-backed log, reading it back once right before it's planted. Also adds `docs/how_seeding_works.md`, describing the full current pipeline.                                                                       | For a large, badly-ordered seed run, a meaningful fraction of records end up waiting a long time. This trades a bounded amount of disk I/O for memory that would otherwise sit idle for however long that wait lasts. It's opt-in because that trade only pays off on large/highly-referential/badly-sorted data -- on small or well-ordered data it's pure overhead.              |
| 7   | `90b0f1a` Add opt-in `prune_unreferenced_records`: skip retaining ids nothing references        | `SprigRecordStore` (commit 4) still kept _every_ planted record's id for the whole run, since it had no way to know whether something later would reference it back. A new prescan (`ReferenceScanner`) finds every `sprig_record(Klass, id)` reference across every source file before planting starts; the store then only retains an id that prescan actually found. | Directly measured via `ObjectSpace`: at large scale the store retains 73.2% fewer ids (147,566 vs. 550,020), and storage-space-over-time drops 11.6%. But the prescan has a real, mostly-fixed cost, so at medium/small scale it's a net _loss_ (+33.8% storage-space-over-time at medium tier) -- opt-in, and worth measuring against your own seed data's shape before enabling. |

## Notes on how this branch was built

- Commits 1-6 are the code changes from an earlier, larger investigation (which also
  included extensive benchmarking infrastructure); commit 7 is new. Each commit here
  contains only the `lib/`/`spec/`/`docs/` changes for that step -- no benchmarking
  scripts, generators, or result docs.
- Each commit is independently the net result of its original implementation plus any
  follow-up refinement made to it before the next part began, so this is 7 clean,
  reviewable steps rather than a longer sequence of "fix" commits.
- All specs pass at every commit on this branch (161 at commit 1, growing to 246 by
  commit 7, as each part brings its own new coverage). `standardrb` reports the same 11
  pre-existing style issues at every commit that `master` itself already has (unrelated
  spec/fixture files this work never touches) -- these happen to be incidentally cleaned
  up to 3 by the final commit's own edits, not fixed on purpose.
